Q2: [CLO2] Code Completion - Chain of Responsibility Pattern Marks: 6

Complete the following Chain of Responsibility pattern for a login validation system. Each handler validates a specific aspect of the login request.

// Base Handler public abstract class Handler { private Handler ________; // Blank 1 public Handler setNext(Handler next) { this.next = ________; // Blank 2 return next; } public final void handle(LoginRequest request) { if (process(request)) { if (next != null) next.________(request); // Blank 3 } } protected abstract boolean ________(LoginRequest request); // Blank 4 } // Concrete Handler public class EmptyFieldHandler extends ________ { // Blank 5 @Override protected boolean process(LoginRequest request) { if (request.username.isEmpty()) { System.out.println("Username cannot be empty"); return false; } return true; } } // Client code public static void main(String[] args) { Handler chain = new EmptyFieldHandler(); chain.________(new LengthCheckHandler()); // Blank 6 chain.handle(new LoginRequest("user@email.com", "pass123")); }
Complete Code Answer
public abstract class Handler { private Handler next; public Handler setNext(Handler next) { this.next = next; return next; } public final void handle(LoginRequest request) { if (process(request)) { if (next != null) next.handle(request); } } protected abstract boolean process(LoginRequest request); } public class EmptyFieldHandler extends Handler { @Override protected boolean process(LoginRequest request) { if (request.username.isEmpty()) { System.out.println("Username cannot be empty"); return false; } return true; } } public static void main(String[] args) { Handler chain = new EmptyFieldHandler(); chain.setNext(new LengthCheckHandler()); chain.handle(new LoginRequest("user@email.com", "pass123")); }

Blank Answers:

Blank 1: next | Blank 2: next | Blank 3: handle | Blank 4: process | Blank 5: Handler | Blank 6: setNext

الشرح:

ده Chain of Responsibility Pattern من Lec 9 (Slides 14-19). الـ Base Handler بيحتوي على reference للـ Handler اللي بعده في السلسلة اسمه next. الـ setNext() method بتسمح لنا نربط الـ Handlers ببعض وبترجع الـ Handler الجديد عشان نقدر نعمل method chaining. الـ handle() method بتستدعي process() method اللي بتعمل المعالجة الفعلية. لو الـ process رجعت true، الطلب بيتمرر للـ Handler اللي بعده. كل Concrete Handler زي EmptyFieldHandler بيعمل extends للـ Handler ويطبق الـ process() method بطريقته الخاصة. في الـ Client code، بننشئ السلسلة باستخدام setNext() وبنستدعي handle() على أول Handler.

Q3: [CLO2] Code Completion - Command Pattern Marks: 10

Complete the following Command pattern implementation for a smart home automation system. The system controls a SmartLight device.

// Command Interface interface Command { void ________(); // Blank 1 } // Receiver class SmartLight { public void ________() { // Blank 2 System.out.println("Smart Light: ON"); } public void switchOff() { System.out.println("Smart Light: OFF"); } } // Concrete Command 1 class LightOnCommand implements ________ { // Blank 3 private SmartLight ________; // Blank 4 public LightOnCommand(SmartLight light) { this.light = ________; // Blank 5 } @Override public void execute() { light.________(); // Blank 6 } } // Concrete Command 2 class LightOffCommand implements Command { private SmartLight light; public LightOffCommand(SmartLight light) { this.light = light; } @Override public void ________() { // Blank 7 light.switchOff(); } } // Invoker class HomeController { private Command command; public void ________(Command command) { // Blank 8 this.command = command; } public void pressButton() { if (command != null) { command.________(); // Blank 9 } } } // Client code public static void main(String[] args) { SmartLight light = new SmartLight(); Command lightOn = new LightOnCommand(light); HomeController controller = new ________(); // Blank 10 controller.setCommand(lightOn); controller.pressButton(); }
Complete Code Answer
interface Command { void execute(); } class SmartLight { public void switchOn() { System.out.println("Smart Light: ON"); } public void switchOff() { System.out.println("Smart Light: OFF"); } } class LightOnCommand implements Command { private SmartLight light; public LightOnCommand(SmartLight light) { this.light = light; } @Override public void execute() { light.switchOn(); } } class LightOffCommand implements Command { private SmartLight light; public LightOffCommand(SmartLight light) { this.light = light; } @Override public void execute() { light.switchOff(); } } class HomeController { private Command command; public void setCommand(Command command) { this.command = command; } public void pressButton() { if (command != null) { command.execute(); } } } public static void main(String[] args) { SmartLight light = new SmartLight(); Command lightOn = new LightOnCommand(light); HomeController controller = new HomeController(); controller.setCommand(lightOn); controller.pressButton(); }

Blank Answers:

Blank 1: execute | Blank 2: switchOn | Blank 3: Command | Blank 4: light | Blank 5: light | Blank 6: switchOn | Blank 7: execute | Blank 8: setCommand | Blank 9: execute | Blank 10: HomeController

الشرح:

ده Command Pattern الكامل من Lec 10 (Slides 24-36). أول حاجة عندنا الـ Command interface بيحتوي على method واحدة اسمها execute(). الـ Receiver هو SmartLight class اللي بيحتوي على الـ methods الفعلية زي switchOn() و switchOff(). بعدين عملنا Concrete Commands زي LightOnCommand و LightOffCommand، كل واحد بيعمل implements للـ Command interface وبيمسك reference للـ Receiver (SmartLight). لما نستدعي execute() على الـ Command، هو بيستدعي الـ method المناسبة على الـ Receiver. الـ HomeController (Invoker) بيمسك Command وبيستدعي execute() عليه من خلال setCommand() و pressButton(). كده فصلنا الـ UI (الزرار) عن الـ Business Logic (تشغيل الإضاءة).
